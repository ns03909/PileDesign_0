## なぜスクリプト化するのか

ジャパンパイルのカタログは Adobe InDesign 出力の CID フォント PDF で、`pdftotext` では日本語が壊れる
(BF.S は Illustrator 出力で壊れないが、表の列対応は結局座標が要る)。
PyMuPDF は文字も座標も正しく取れるため、**目視転記より機械抽出の方が確実**。
(過去に PDF の目視転記で係数を 3 箇所誤った事例がある)

## 抽出の要点

`extract.py` は表の**罫線**からセル格子を作る。単純な y クラスタリングでは
縦結合セル (呼び名・Fc・肉厚など) を取り違えるため。

| 論点 | 対処 |
|---|---|
| 縦結合セル | 列ごとに「行境界に罫線があるか」を調べて span を確定し、値を span 内の全行へ複製 |
| **断面性能表には縦結合が無い** | `expand_merged=False`。罫線が一部欠けている列で上の行の値が下へ複製される事故が実際に Ze 列で発生した |
| 千位が半角スペース区切り | `'1' + '000'` が別単語になる。x 間隔で連結 (`merge_number_tokens`) |
| 節部径が呼び名セルへ食い込む | 呼び名 `Do-D` 自体が節部径・軸部径なので**呼び名から導出**し、列側は桁列の一致で照合するだけにする |
| 諸数値表と性能表の対応 | 別ページだが**行順が完全に一致**する。データ行数の一致を assert してから index で join |

### NPRC で追加で踏んだ罠

| 論点 | 対処 |
|---|---|
| ヘッダー行数がページごとに違う (2 行 / 3 行) | 行数を決め打ちせず**内容で**データ行を判定する (諸数値ページ=種類がローマ数字 / 性能ページ=先頭列が数値) |
| 罫線の無い列 (せん断補強筋) がヘッダー文字ごと 1 セルに結合される | 上記でヘッダーを除いた y 範囲に絞ってから結合展開する |
| PRC部 と PHC部 の表が横並びで、その間に垂直罫線が無い | `PERF_SPLIT_X` で領域を左右に分けて 2 回抽出する。融合すると PRC の N 列と PHC の Ae 列が 1 列になる |
| PHC部 は PRC部 より行数が少ない (製品グループ単位) | 行番号ではなく **y 位置**で PRC の各行に対応付ける |
| 同じページの別の表の垂直罫線が列境界に混入する | 罫線を「位置」だけでなく「伸びている範囲」でも絞る (`extract.py`)。表の左右端も水平罫線の到達範囲から決める |
| 厚さ仕様が縦書きで字順が崩れる (`厚特`) | `normalize_thickness` で復元する |
| p8 の付表 (標準質量表・拡頭形状一覧) は小表が横並びで、行境界の罫線が無い列がある | 小表ごとに x 範囲を切って抽出し、罫線の無い列 (呼び名・Lt) は `column_by_y` で座標から行に配り直す |
| 縦結合セルの文字は**結合範囲の中央**に置かれる | 単語の y が入る行帯をそのまま採ると 1 行ずれる。値どうしの中点を境界にして最寄りの値を割り当てる |

## 検算が品質保証の主役

節杭の断面性能はすべて**軸部**の中空円形断面から一意に決まる。
`TestProject1/NodularPileLibraryTests.cs` が NPH 全 292 行を、
`NodularPrcPileLibraryTests.cs` が NPRC 全 232 行を計算値と突合する。

```
Ao = π/4 (D² − di²)                     di = D − 2t
Io = π/64 (D⁴ − di⁴)
Ae = Ao + (n − 1) Ap                    n = Ep / Ec
Ie = Io + (n − 1) Ap (PCD/2)² / 2
Ze = Ie / (D/2)
```

カタログは有効数字 3〜4 桁に丸められているので相対 0.15% を許容する
(桁の転記ミスは 1% 以上ずれるので確実に検出される)。実測の最大相対差は 0.09%。

NPRC は異形棒鋼 (SD345) を併用する PRC 断面なので、換算比が 2 つになる。
`build_nprc.py` は CSV を書く前に自分で全行を検算し、合わない行があれば `AssertionError` で止まる
(`TestProject1/NodularPrcPileLibraryTests.cs` が同じ検算を C# 側でも行う)。

```text
Ae  = Ao + (np − 1) Ap + (nr − 1) Ag              np = Ep/Ec = 5.0
Ie  = Io + (np − 1) Ap (PCD/2)²/2
         + (nr − 1) Ag (BarPCD/2)²/2              nr = Er/Ec = 5.125
So  = (D³ − di³)/12                               断面 1 次モーメント
PHC部 は異形棒鋼を持たないので (nr − 1) の項が落ちるだけ
```

> **`Er = 205 000` は p1「設計に用いる諸定数」の異形棒鋼 (SD345) の値**。
> PC 鋼棒の `Ep = 200 000` と違うので、両方を 200 000 とすると Ae/Ie が合わない。

### 検出したカタログ誤植

**NPH**: φ700-600 と φ800-600 の **Fc123・AH 種**の `Ze` が、直上行 (A 種) と同じ `16 430×10³`
で印字されている。同じ行の `Ie = 543 400×10⁴` から `Ze = Ie/(D/2) = 18 113×10³` が正しく、
Fc105 の対応行も `18 130×10³` である。CSV では印字値を `Ze` に忠実に残しつつ、
`Note` 列に注記し、`ZeFromIe` 列に正しい値を入れている。**利用側は `ZeFromIe` を使うこと。**

**BF.S / MS-hi105**: 検算では誤植は見つかっていない。

**DAM105**: **φ400 厚型 A-D16** の主筋断面積が `13.39cm²` と印字されているが、
7-D16 = `13.90cm²` が正しい (同じ製品の他の肉厚仕様も 13.90 で、換算断面積 Ae も
13.90 で計算されている)。公称断面積との突合で検出し、正しい値へ置き換えて `AsNote` に注記。

**Hi-SC105**: 腐食代1mm 表の **φ1200 特厚型**の杭断面積 `Ao` が `5 911cm²` と印字されているが、
同じ行の `Ac + As = 5 991cm²` が正しい。縦結合セルなので 17 行が同じ値。
取り込み時に `Ac + As` へ置き換え、`Corr1Note` 列に理由を残している
(製品として取り込む腐食代0mm 側には誤植は無い)。

**NPRC**: **φ700 (t=100)** の全 18 行の `So` が `18 617×10³` と印字されているが、
`(D³ − di³)/12 = 18 167×10³` が正しい (桁の入れ替わり)。同じ φ700 でも t=120 の行は正しい。
CSV は印字値を `So` に残し、`SoFromSection` 列に正値・`Note` 列に注記を入れている。
**利用側は `SoFromSection` を使うこと。**

## カタログに無い情報 (推定値)

姿図には節ピッチ 1000mm・杭頭から第1節中心 600mm・杭先端から最終節中心 400mm・
拡頭部長さ Lt 600mm の寸法記入があるが、**節そのものの寸法 (節部長さ・テーパー長) は
寸法記入が無い**。

姿図のベクタ座標を実測したところ、テーパーは厳密に 45° (dx = dy = 4.16pt) だった。
よって `NodularPile.EstimatedTaperLength = EstimatedNodeFlatLength = (Do − D)/2` を
**推定値**として持たせている (プロパティ名の `Estimated` と XML コメントで明示)。
姿図自体が特定製品の縮尺ではない (軸部 599mm・節部 749mm 相当という実在しない寸法) ため、
公称寸法ではない。**形状表示以外に使ってはならない。**
確定値が必要な場合はメーカーに確認すること。

## BF.S (三谷セキサン) はカタログに書いていない量を 2 つ補っている

この製品は「頭部厚型節付き杭」で、1 本の杭が**外径の違う 2 つの軸部**から成る。
内径は完全に一致していて (D<sub>T</sub>−2T<sub>T</sub> = D<sub>0</sub>−2T)、頭部だけが外側に厚い。
そして**標準性能表は頭部軸部の値しか載せていない** (表の注記)。

| 補った量 | 方法 | 裏付け |
|---|---|---|
| 配筋径 PCD | 頭部軸部の `Ie` から逆算 | 同一呼び名なら Fc・種類によらず一致し、5mm 丸めに乗る (240/335/420/510/600/690/790/890/980) |
| 先端軸部の断面諸元・σce | 有効プレストレス力 σce·Ae が両軸部で共通という前提で算定 | 結果の σce が JIS A 5373 の A/B/C 種の規定値 (4 / 8 / 10 N/mm²) に ±5% で乗る |

**2 つ目が 1 つ目の独立した検算になっている**点が重要。PCD の逆算か
プレストレス力一定の仮定のどちらかが外れていれば、先端軸部の σce は JIS 値から外れる。

先端軸部の耐力 (M<sub>cr</sub> / M<sub>u</sub> / Q<sub>as</sub> 等) はカタログに存在しないので、
アプリ側の断面計算 (`PHCSection`) の結果をそのまま設計値として使う。
頭部軸部については、その計算値がカタログの M<sub>u</sub> と全 27 製品で +2〜7% に収まることを
`TestProject1/BfsPileSectionTests.cs` が固定している (先端軸部を計算値で扱う根拠)。

なお**このカタログには標準質量表が無い**ので、自重は軸部体積から求まる (節の分は未計上)。

## MS-hi105 だけ罫線ベースが使えない

この表は<b>行の区切りが線ではなく背景の塗り矩形の縁</b>で表現されていて、
`get_drawings` から水平線として取れない。列の垂直線は取れるので `build_pmc.py` は

| 要素 | 求め方 |
|---|---|
| 列境界 | 垂直罫線 (線分に分かれているので同じ x でまとめてから、表本体を縦断するものだけ採る) |
| 行境界 | 行が等ピッチであることを使って算術的に作る。基準は必ず 1 行 1 値になる `Ae` 列 |
| 縦結合 | 結合セルの文字が結合範囲の**中央**に置かれることから span を厳密に解く |

としている。span の解が行数とぴったり合うことがそのまま検算になっている。

**中点で分ける近似は使えない。** 隣り合う結合の行数が違うと境界行を取り違えるため
(この表は φ300 が 3 行結合・φ400 が 9 行結合など不揃い)。
開始行 a が決まれば終了行は b = 2p − a (p は文字中心の行番号) で決まるので、
先頭 a=0 から鎖のように解く。

ただし**結合行数が偶数のときは中央が行と行の境目になり**、文字がどちらの行に置かれるかで
半行ぶんの曖昧さが残る。本体部径がこれに当たる (φ1100 は 8 行結合) ので、
径だけは `Ao = πT(D−T)` から解き、印字されている径の一覧と一致することで照合している。

なお「JIS A 5373 ひびわれ曲げモーメント」列は縦結合の罫線が部分的に欠けていて
確実に切り分けられないため**取り込んでいない** (曲げ耐力の `Mcr` が別列にあり、そちらで足りる)。

## Hi-SC105 は腐食代 1mm の表が検証データになる

このカタログは<b>腐食代 0mm と 1mm の両方</b>の標準性能表を持つ。本プログラムは腐食を
製品ではなく `CorrosionDepth` パラメータとして扱うので、製品としては 0mm 側だけを取り込み、
1mm 側は CSV の `Corr1*` 列に併記している。
`TestProject1/HiSc105PileLibraryTests.cs` がこれを使って<b>腐食モデルを外部データで検証</b>する
(腐食後の鋼管断面積・曲げ剛性)。他の 4 カタログには無かった検証手段。

抽出上の注意:

| 論点 | 対処 |
|---|---|
| 行の罫線が列ごとに分かれた短い線分 | 行境界は表を横断する長い線で決め、縦結合の判定には分割前の線分も使う |
| 行境界の線が 1 本だけ描かれていないブロックがある | 行は等ピッチなので抜けを補間する。補間した境界は「線が無いだけで行境界ではある」ものとして縦結合判定にも効かせる (これをしないと見出しが 1 行目のセルへ流れ込む) |
| 肉厚 T は鋼管 + コンクリートの<b>全肉厚</b> | `Ao = πT(D−T)` が成り立つことで確認できる。コンクリート厚は T − ts |
| 肉厚仕様が縦書きで、群がページをまたぐと「型」が落ちる | 正規化したうえで、径ごとに 標準型 < 厚型 < 特厚型 の順に肉厚が増えることで検算する |

### カタログの Ie は厳密式より少し小さい

`Ao` / `Ac` / `As` / `Ae` は印字の丸め以内で一致するが、`Ie` だけは
<b>鋼管が厚いほど計算値が印字を上回る</b> (φ400 ts=20 で +0.22%)。
鋼管の断面二次モーメントを薄肉近似で出しているためと見られる。
本プログラムは EI を自前で積算するので取り込みには影響しないが、
カタログ `Ie` をそのまま使う場合はこの差に注意すること。

## DAM105 は配筋径を 2 円モデルで解く

このカタログも配筋径を印字していないが、Hi-SC105 までと違って
**PC鋼棒と異形鉄筋という 2 群**があるので、Ie 1 本からは決まらない。

そこで<b>同じ断面 (D, 肉厚) に種類 (主筋径) 違いが複数ある</b>ことを使う。
主筋の円はかぶりが一定なら鉄筋径が太いほど内側へ寄る (dr = D − 2c − db) ので、

```text
Ie = Io + (n−1)/2 · [ Ap·rp² + As·(R0 − db/2)² ]      未知数は rp と R0 の 2 つ
```

として最小二乗で解く。R0 を 1 次元探索し、各 R0 で rp² を線形最小二乗で求める。
**残差 RMS は全 35 断面で 0.11% 以内**に収まり、これがモデルの裏付けになっている
(単一円と置くと同じ断面内で逆算値が 10mm 以上ばらつく)。

`TestProject1/Dam105PileLibraryTests.cs` が、逆算した配筋径から Ie を組み直して
カタログ値に戻ること・主筋が太いほど配筋円が内側へ寄ることを固定している。

### せん断耐力は参考値なので設計値にしない

カタログ自身が「**設計せん断耐力の値に関しては、参考としてシアスパン比 a=1.0 の時の値を
記載しております。実際の設計において使用する値は、別途計算式により求める必要があります**」と
注記している。そのため `Ref*` 列に置き、既存ローダーが読む 28 列には入れていない。

### 見出しとデータ 1 行目の間の罫線が無い

放置すると見出し文字が 1 行目のセルへ流れ込む。行が等ピッチなので抜けた境界を算出し、
`extract_table(extra_hlines=...)` で補う。左右 2 表は行位置が微妙に違うので<b>表ごとに</b>求める。

## 他社カタログを追加するとき

CSV スキーマはメーカー横断の汎用形式。`Maker` / `Series` / `Shape` 列を変えて
同じ CSV に追記すればよい。`extract.py` は罫線ベースなので、表の体裁が違えば
`extract_table()` の呼び出し範囲と列マッピングだけ書き直す。
追加後は必ず上記の検算テストを通すこと。
